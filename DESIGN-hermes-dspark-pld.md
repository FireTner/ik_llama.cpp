## Problem Statement

Run Bonsai-27B (Q1_0_G128, qwen35 hybrid) locally for Hermès with `-c 65536` on an RTX 4060 Laptop 8GB so multi-turn agent sessions *feel instantaneous*: snappy tool turns, sustained decode, no UVM paging, no output→CPU VRAM wash. Baseline without DSpark is ~35 t/s short / ~24 t/s at ~20k. Exhaust optimizations, but ship the stack that wins session feel — not just synthetic tg.

## What Makes This Cool

Three layers that match real Hermès traffic:

1. **DSpark** drafts freeform tokens (decode lift vs ~24 t/s baseline) while IO-tensor sharing keeps the draft on an 8GB card at 64k.
2. **Hybrid-correct checkpoints** so tool turns restore instead of re-PP’ing 20k tokens (the actual “instant” feeling).
3. **Prompt-lookup / n-gram (PLD)** for templated tool-call JSON boilerplate at near-zero VRAM — DSpark only spends cycles on the unpredictable continuation.

The whoa is personal: *your* overnight Hermès loop stops stalling. Bonus: a reproducible laptop-64k speculative playbook.

## Constraints

- Hermès hard requirement: `-c 65536` (do not shrink).
- Never `GGML_CUDA_ENABLE_UNIFIED_MEMORY`.
- Keep `-ngl 99` so `output.weight` stays on GPU; never `-ngl ≤64` (compute buffer wash).
- Prefer q4_0 KV + Hadamard over TurboQuant chase for this setup.
- ~14GB system RAM; desktop often ~1.0–1.2GB VRAM.
- Primary audience: you mid-Hermès run. Baseline for comparison: current non-DSpark stack.
